# Rev.AI 🤖

> AI-powered guest review intelligence for hospitality businesses — built with React, Express, MongoDB Atlas, and Google Gemini AI.

Rev.AI instantly classifies guest reviews by **sentiment** (positive / neutral / negative), detects the primary **theme** (food, host, location, cleanliness, value, experience), and generates a professional **management response** — all powered by **Google Gemini AI** and persisted to MongoDB.

- **Backend:** Node.js, Express.js (MVC Architecture), Passport.js, JWT, bcryptjs, Helmet, CORS

- **Hosting & Infrastructure:** Vercel (Frontend), Render (Backend Service), MongoDB Cloud Atlas (Database)

### ⚠️ Known Limitations on Free Tier

1. **Render Free Tier Cold Starts (Backend):**
   - The backend service on Render automatically spins down after **15 minutes of inactivity**.
   - The **first request** after an idle period takes **30 to 60 seconds** to wake up and respond.
   - Subsequent requests process at normal speeds (< 500ms).

2. **MongoDB Atlas M0 Free Tier (Database):**
   - Storage limit is capped at **512 MB**, which is plenty for thousands of review records.
   - Connection pool is capped at **100 concurrent connections**.

3. **Gemini AI API Free Tier Quota:**
   - AI endpoints are rate-limited to **30 requests per 10 minutes** per user to avoid hitting API rate limits.
   - Fallback mechanisms handle temporary API throttling gracefully.

## 🧠 Gemini AI Integration (Week 7)

Rev.AI uses **Google Gemini 2.5 Flash** (via OpenRouter) to power its core review analysis engine. Every review submitted by a user is sent to the Gemini API, which returns structured JSON containing sentiment classification, theme detection, and a professional management response.

### AI Workflow

```
User enters review → Frontend POST request → Express Backend → Gemini API → AI Response → MongoDB Save → Display Results
```

### AI Features

| Feature | Description |
|---|---|
| 🔍 Sentiment Analysis | Gemini classifies reviews as positive, neutral, or negative |
| 🏷️ Theme Detection | AI detects 6 categories: food, host, location, cleanliness, value, experience |
| 💬 Response Generation | Gemini generates professional management responses |
| 📝 Summarization | `POST /api/ai/summarize` — AI-powered text summarization |
| 💡 Recommendations | `POST /api/ai/recommend` — AI-generated improvement recommendations |
| 💬 Chat | `POST /api/ai/chat` — General AI assistant for hospitality queries |

### Prompt Engineering

Three prompt templates were evaluated for production use. See [PROMPTS.md](./PROMPTS.md) for the full comparison, example inputs/outputs, and rationale.

**Selected Prompt:** Strict JSON Analyzer — chosen for 99%+ parse reliability and direct MongoDB schema alignment.

### Error Handling & Fallbacks

- If Gemini API is unavailable, the system falls back to keyword-based analysis
- All AI errors are caught and return safe, user-friendly messages
- Rate limiting prevents API abuse (30 requests per 10 minutes per user)

## 🗄️ Database Choice

**MongoDB Atlas (Free Tier)** was chosen for this project for the following reasons:

| Reason | Detail |
|---|---|
| **Document model** | Each review is a self-contained JSON document — no joins needed |
| **Schema flexibility** | Easy to add new fields (e.g. AI scores) without migrations |
| **Atlas free tier** | 512MB hosted cluster — zero infrastructure cost for this project |
| **Mongoose ODM** | Provides schema validation, indexing, and clean query API |
| **Text search built-in** | Native `$text` index powers keyword search across review fields |

## 📊 Schema Diagram

![Rev.AI MongoDB Schema](./W5_SchemaDiagram_TBI-26100834.png)

> **Collection:** `week5db.reviews`  
> **Indexes:** Text index on `reviewText + response + theme` | Compound index on `sentiment + theme + analyzedAt`

### Field Reference

| Field | Type | Validation | Notes |
|---|---|---|---|
| `_id` | ObjectId | Auto | Primary key, generated by MongoDB |
| `reviewText` | String | Required, 5–5000 chars | The raw guest review |
| `sentiment` | String | Enum: positive/neutral/negative | Classified by Gemini AI |
| `theme` | String | Enum: food/host/location/cleanliness/value/experience | Detected by Gemini AI |
| `themeIcon` | String | — | Emoji icon mapped from theme |
| `response` | String | Required | AI-generated management response |
| `analyzedAt` | Date | Default: now | When the review was analyzed |
| `createdAt` | Date | Auto (timestamps) | Mongoose auto-field |
| `updatedAt` | Date | Auto (timestamps) | Mongoose auto-field |

## 🚀 Quick Start

### Prerequisites

- **Node.js** v18+ — [Download](https://nodejs.org)
- **MongoDB Atlas** account (free tier) — [Sign up](https://www.mongodb.com/cloud/atlas)
- **Gemini API Key** — [Get one from Google AI Studio](https://aistudio.google.com/app/apikey) or [OpenRouter](https://openrouter.ai/)

---

### Step 1 — Clone the Repository

```bash
git clone https://github.com/ravi0-web/REV.AI.git
cd REV.AI
```

---

### Step 2 — Set Up the Database (MongoDB Atlas)

1. Go to **[cloud.mongodb.com](https://cloud.mongodb.com)** and sign in
2. Click **Build a Database** → choose **Free (M0 Sandbox)**
3. Choose a cloud provider & region → click **Create**
4. **Security → Database Access** → Add a new database user
5. **Security → Network Access** → **Allow Access from Anywhere** (`0.0.0.0/0`)
6. **Database → Connect → Connect your application** → copy the URI

---

### Step 3 — Configure Environment Variables

```bash
cd server
cp .env.example .env
```

Open `server/.env` and fill in your values:

```env
PORT=5000
NODE_ENV=development
MONGO_URI=mongodb+srv://youruser:YourPassword@cluster0.xxxxx.mongodb.net/week5db?retryWrites=true&w=majority

# JWT Authentication
JWT_SECRET=your_jwt_secret_here

# Gemini AI (via OpenRouter)
GEMINI_API_KEY=your_openrouter_api_key_here

# Frontend Origin (for CORS)
CLIENT_ORIGIN=http://localhost:5173
```

> ⚠️ **Never commit `.env`** — it contains your database credentials and API keys. Only `.env.example` is committed.

---

### Step 4 — Install Dependencies

```bash
# Backend
cd server && npm install

# Frontend
cd ../client && npm install
```

---

### Step 5 — Run the Application

**Terminal 1 — Backend:**
```bash
cd server
node server.js
```

You should see:
```
✅  MongoDB connected: cluster0.xxxxx.mongodb.net
🚀  Rev.AI server running on  http://localhost:5000
```

**Terminal 2 — Frontend:**
```bash
cd client
npm run dev
```

Open **[http://localhost:5173](http://localhost:5173)**

## 🌐 API Documentation

Base URL: `http://localhost:5000/api`

### Review Endpoints (MongoDB-powered)

| Method | Endpoint | Description | Auth | Status Codes |
|---|---|---|---|---|
| `GET` | `/api/health` | Server + DB health check | No | 200 |
| `POST` | `/api/reviews/analyze` | Analyze & save reviews (Gemini AI) | Yes | 201, 400 |
| `GET` | `/api/reviews` | Get all reviews (paginated) | Yes | 200 |
| `GET` | `/api/reviews/stats` | Aggregated dashboard statistics | Yes | 200 |
| `GET` | `/api/reviews/search` | Full-text search + filter | Yes | 200, 400 |
| `GET` | `/api/reviews/filter` | Filter by sentiment/theme | Yes | 200, 400 |
| `GET` | `/api/reviews/:id` | Get single review by ObjectId | Yes | 200, 404 |
| `DELETE` | `/api/reviews/:id` | Remove one review | Yes | 204, 404 |
| `DELETE` | `/api/reviews` | Clear all history | Yes | 200 |

### AI Endpoints (Gemini-powered)

| Method | Endpoint | Description | Auth | Status Codes |
|---|---|---|---|---|
| `POST` | `/api/ai/chat` | General AI chat | Yes | 200, 400, 429, 500 |
| `POST` | `/api/ai/summarize` | AI text summarization | Yes | 200, 400, 429, 500 |
| `POST` | `/api/ai/recommend` | AI improvement recommendations | Yes | 200, 400, 429, 500 |

### Auth Endpoints

| Method | Endpoint | Description | Auth | Status Codes |
|---|---|---|---|---|
| `POST` | `/api/auth/register` | Create new user account | No | 201, 400, 409 |
| `POST` | `/api/auth/login` | Login with email/password | No | 200, 401 |
| `GET` | `/api/auth/me` | Get current user profile | Yes | 200, 401 |
